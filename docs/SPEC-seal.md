# 🃏 シールコレクションアプリ 仕様書

> **実装状況**: `seal/` に実装済み(アプリ名: **シールアルバム**)。

**鬼滅の刃 ディフォルメシールウエハース 其ノ十五** のシールを、
スマホで写真に撮って集めていくコレクションアプリ。

既存アプリ(かいわすれナシ!・スポカレ!・ふくらぶ・ピコラン!・ハナビカメラ・
キタイベ!・ジャマケシ・おてつだいバンク・バスナビ!)と同じ構成で作る:

- ビルド不要・単一HTML(`seal/index.html`)・依存ライブラリなし
- PWA対応(ホーム画面に追加してフルスクリーンで起動)
- 写真は端末の外に一切送信しない(処理はすべてブラウザ内で完結)

## 決定事項

| 項目 | 決定 |
|---|---|
| 対象商品 | 鬼滅の刃 ディフォルメシールウエハース 其ノ十五(2026年8月3日発売・全39種、シークレット3種を含む) |
| シール一覧 | **No.1〜No.39 の空き枠を用意し、名前とレアリティはユーザーが入力する**。公式のキャラ名リストは埋め込まない |
| 自動判別 | **「登録ずみのシールと同じか」を写真から見分けて、名前とレアリティを引き継ぐ**。はじめて見るシールのキャラ名は当てない(端末内で完結させるため画像認識モデルは載せない) |
| レアリティの自動 | **キラ(箔)かどうかだけを推定**し、ノーマル/レアを先に選んでおく。5thレア・無限レア・シークレットの区別はしない |
| 名前の入力補助 | 作品の登場人物名をサジェストとして出す。あくまで入力補助で、公式ラインナップ表ではない旨を明記する |
| 中核機能 | **あらかじめ用意された枠に写真をはめていく**。枠を選ぶ → 撮る → 四隅の自動検出 → 台形補正 → 背景の透明化 → 枠にフィット、までを操作なしで通す |
| 入れる枠 | **撮る前に決める**。アルバムの空き枠をタップするとカメラが開き、撮った写真はその枠に入る。撮ってから番号を選ぶ画面は作らない |
| 切り抜きの調整 | ふだんは**全自動**。四隅のドラッグは「切り抜きを直す」から任意で開く逃げ道として残す |
| 保存する形 | **正方形(760x760)の枠のまん中に、同じ余白で収める**。並べたときに大きさがそろう |
| 処理場所 | **完全に端末内**。API キーも通信も使わない |
| 保存先 | **IndexedDB**。写真は Blob、状態は JSON。localStorage は写真に容量が足りないので使わない |
| ダブり | 枠ごとに**所持枚数**を持ち、2枚以上をダブりとして扱う |
| 交換 | ダブり・未所持の一覧と、そのままコピーできる**交換募集の文面**を自動生成する |
| レアリティ | 未設定/ノーマル/レア/5thレア/無限レア/シークレット。色分け表示と種類別コンプ率 |
| 入手メモ | 日付は自動記録。場所・値段のような細かい家計簿機能は作らない(自由メモ1行のみ) |
| 弾の切り替え | 作らない。枠数とアルバム名を変更できるようにして代替する |

## 画面構成

下タブで4画面を切り替える。ヘッダーの下に常時コンプ率(リング+のこり種類数)を表示。

| タブ | 内容 |
|---|---|
| 📒 アルバム | 39枠のマス目。絞り込みチップ(すべて/未所持/所持ずみ/ダブり/写真なし/レアリティ別) |
| 🔁 こうかん | ダブり一覧・未所持一覧・交換募集の文面(コピー/共有) |
| 📊 しんちょく | レアリティ別コンプ率のバー、手に入れた日ごとの記録 |
| ⚙️ データ | アルバム名、枠数の増減、バックアップの書き出し/読み込み、やりなおし |

### 撮影の流れ

```
アルバムの空き枠をタップ (または 📷 = いちばん若い空き枠)
        ↓
カメラ (見出しに「No.5 の枠に入れる」と出る)
        ↓  シャッター
四隅の検出 → 台形補正 → 背景の透明化 → 枠にフィット   … すべて自動・操作なし
        ↓
その枠に登録 → 名前とレアリティの画面が開く
        ↓
別の枠に同じシールがありそうなら「No.3 と同じに見えます」と知らせる
```

やり直しの導線は名前の画面に置く。

- **✂️ 切り抜きを直す**: 直前に撮った元画像に対して四隅のドラッグ画面を開く
  (元画像は保存せずメモリ上にだけ持つので、撮った直後だけ使える)
- **↔ 枠を移す**: 写真・指紋・自動で入れたレアリティを別の枠へ移す。
  移す先に名前が入っていなければ名前とメモも連れていき、名前のある枠(あらかじめ用意した枠)へ
  移すときはその枠の名前を尊重する
- 空き枠の**長押し**で、撮る前に名前やレアリティを入れる画面を開く

そのほかの画面(オーバーレイ):

- **カメラ**: 全画面プレビュー・シャッター・インアウト切替・ライト・写真から選ぶ。
  カメラが使えないときはエラー表示と「🖼 写真から選ぶ」を出し、操作不能にならないようにする
- **切り抜きを直す**: 四隅のドラッグ、虫めがね、自動検出やり直し、写真全体、90度回転、
  「まわりを透明に」の切り替え、右上に**できあがりの見本**
- **枠を移す**: 移動先の枠を選ぶ。同じシールが入っていそうな枠は上に候補として出す
- **詳細シート**: 写真・名前・レアリティ・枚数・メモの編集、撮り直し、写真削除

## 画像処理

すべて canvas 上で自前実装する。

### 1. 四隅の自動検出 `detectQuad()`

1. 長辺200pxに縮小
2. 外周の帯から背景色を推定(チャンネルごとの中央値)
3. 背景色との距離を**大津の二値化**でしきい値化してマスクを作る
4. ノイズ除去(収縮→膨張)のあと**連結成分**を求め、いちばん大きいかたまりを選ぶ
   (画面のほぼ全面を覆うものは背景とみなして除外、ふちに接するものは減点)
5. かたまりの**凸包**を取り、面積が最大になる4点を選ぶ(四隅の目安から山登りで改善)
6. 左上→右上→右下→左下に並べ替え、元のサイズに戻す

見つからなければ中央84%の長方形にフォールバックする。

### 2. 台形補正 `warpQuad()`

単位正方形 → 四角形 の射影変換を閉じた式で求め、
出力の各画素から逆に引いてバイリニア補間でサンプリングする。
出力サイズは四辺の長さから決め、長辺760pxに収める。

### 3. 背景の透明化 `removeBackground()`

台紙の白を消して、シールの形だけを残すための処理。

1. ごく外側(2%)の画素を **k-means(k=2)** で分け、背景色を最大2色求める
   (「濃い机の上に白い台紙」のように2色写っていても両方拾えるようにする)
2. ふちの画素をすべて種にして塗りつぶしを広げる。広げる条件は
   **背景色に近い(tol)** か、**そこそこ近く(tolHi)かつ隣と地続き(LOCAL)**。
   2つめは境目のぼけや影をたどるための逃げ道で、上限を付けないとにじみ伝いに本体まで食い込む
3. 残った部分を連結成分に分け、**ごく小さなかけら**と**ふちに残ったにじみの輪**を捨てる
4. 消しすぎ防止のチェック(残りが5%未満 / 残りがバラバラに割れている)に引っかかったら、
   背景色を「多い色だけ」「少ない色だけ」と変えて再挑戦する。それでもだめなら**四角いまま**にする
5. アルファを3x3でぼかしてふちをなめらかにし、残った部分の大きさに切り詰める

透明化できたかどうかを呼び出し側に返し、できたときだけ WebP/PNG(アルファ付き)、
できなかったときは JPEG で保存する。見送ったときはその旨をトーストで伝える。

## 自動判別

### なぜ「キャラ名を当てる」ことをしないか

キャラを見分けるには学習済みの画像認識モデルが要る。端末内で完結させる方針(写真を外に出さない)
と相性が悪く、モデルを同梱するとアプリが数十MB単位で重くなる。同梱の OCR(Tesseract)は英語データ
しか持っておらず、日本語データは15MB超になるうえ、ディフォルメシールにキャラ名が印刷されている
保証もない。そのため**はじめて見るシールの名前は当てない**と決めた。

代わりに「**一度登録したシールと同じか**」だけを見分ける。ウエハースはダブりが大量に出るので、
実際の入力回数はこれでほぼ無くなる。

### シールの「指紋」 `computeSignature()`

切り抜き後の絵から、次をまとめた小さなデータを作って枠に保存する。

| 要素 | 内容 |
|---|---|
| 色 | 4x4 のマスごとの平均RGB。中身がほとんど無いマスは「不明」にして比較から外す |
| 色あい | あざやかな画素の色あいを12段のヒストグラムに(あざやかさで重みづけ) |
| 形 | 8x8 のマスごとの「不透明な画素の割合」 |
| たてよこ比 | 中身の外接矩形の比 |

撮影時の明るさのちがいで別物と判定しないよう、色は画像全体の平均の明るさで割って正規化する。
また透明な余白を除いた中身を 64x64 の中央に形を保ったまま収めてから測るので、
写る大きさが変わっても比較できる。

似ぐあいは `0.36*色 + 0.28*色あい + 0.26*形 + 0.10*たてよこ比` で 0〜1 にする。

### 見分けた結果の使い方

入れる枠は撮る前に決まっているので、**判定結果で勝手に枠を変えることはしない**。
別の枠に同じシールが入っていそうなときに知らせ、選ぶのは利用者にする。

- 似ぐあい **0.62 以上** → 名前の画面に「No.3 竈門炭治郎 と同じシールに見えます（96%）」と出し、
  「ダブりにする」を押すとこの枠の写真を消してその枠の枚数を1増やす
- 「枠を移す」画面でも、同じシールが入っていそうな枠を上に候補として並べる

疑似シール(8種 × 撮り方3通り)での実測:

| 条件 | 1位が正解 | 自動登録が動いた回数 | 誤登録 |
|---|---|---|---|
| 切り抜きに成功した写真どうし | 8/8、7/8 | 5/8 | **0** |
| 片方が切り抜きに失敗した写真 | 7/8 | 0 | **0** |

切り抜きに失敗した写真では自動登録が動かず候補提示にとどまる(＝安全側に倒れる)ことも確認した。

### キラ(箔)の見分け `estimateShine()`

箔は「となり合う画素で色あいがバラバラに変わる」のが特徴。ふつうの印刷は同じ色の面が続くので、
色あいの変化はふちだけに限られる。これに、こまかい白飛びの粒(きらめき)を足して判定する。
露出オーバーの大きな白飛びは粒として数えないことで、明るすぎる写真との取りちがえを防ぐ。

`score = 0.65 * min(1, 色あいのばらつき/0.012) + 0.35 * min(1, こまかい白飛びの割合/0.02)`
で、色あいのばらつきが 0.006 以上かつ score 0.6 以上なら箔とみなす。

疑似シールでは 24/24 正解(箔ありの score 0.65〜1.0、箔なし 0.002〜0.21)。
ただし疑似データの「箔でない絵」は色の面が平らすぎるため、**実物の写真での精度は未検証**。
そのため結果は必ず「先に選んでおくだけ」にとどめ、理由を書いて手で直せるようにしている。

## データ構造

```js
// IndexedDB: sealalbum
//   kv     : 'state' → 下のオブジェクト
//   photos : { id, full: Blob, thumb: Blob }
{
  version: 1,
  title: '鬼滅の刃 ディフォルメシールウエハース 其ノ十五',
  slots: [
    {
      no: 1,            // 通し番号(1始まり・表示にも使う)
      name: '',         // シールの名前(ユーザー入力)
      rarity: '',       // '' | 'normal' | 'rare' | 'fifth' | 'mugen' | 'secret'
      count: 0,         // 所持枚数(0=未所持, 2以上=ダブり)
      memo: '',
      photoId: null,    // photos ストアのキー
      gotAt: null,      // 最初に所持した日時(ミリ秒)
      sig: null,        // シールの「指紋」(同じシールかの見分けに使う)
      rarityAuto: false // レアリティを写真から自動で選んだか(手で選ぶと false に戻る)
    },
    // …No.39 まで
  ]
}
```

## バックアップ

- **写真ごと**: 写真を dataURL にして1つの JSON にまとめる
- **文字データだけ**: 写真を含めない軽いファイル(読み込むと写真は消える)
- 読み込みは現在のデータを置きかえる(内容を確認するダイアログを挟む)

## 作らないもの

- サーバー同期・アカウント・SNS投稿機能
- はじめて見るシールのキャラ名の自動認識(AIによる画像認識)
- 5thレア/無限レア/シークレットの自動判別
- 公式ラインナップの埋め込み(誤った情報を配らないため)
