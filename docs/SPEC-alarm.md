# ⏰ 祝日除外アラーム(平日メザマシ)仕様案

> **実装状況**: 未実装(このドラフトで仕様検討中)。
> 実装は `alarm/` フォルダに、既存アプリと同じ構成
> (ビルド不要・単一HTML・PWA・LocalStorage)で作る予定。

「会社・学校がある日だけ鳴る目覚まし」。
平日の決まった時刻に鳴らしつつ、**日本の祝日と自分で登録した休みの日は
自動でスキップ**する。「祝日なのにいつもの時間に起こされた…」をなくすアプリ。

## 決定事項(ヒアリング済み)

- **主用途**: 平日の起床用アラーム
- **除外する日**: 日本の祝日(振替休日・国民の休日含む)+ 自分で指定した日
  (年末年始・会社の休業日・有給など)
- **鳴り方**: アプリを閉じていても通知でほしい(下記「鳴動の3段階」参照)

## いちばん重要な前提: Webアプリで「鳴らせる」範囲

ブラウザアプリ(PWA)は、OS標準の目覚ましと違い
「完全に終了した状態から自力で起動して鳴る」ことができない。
そこで確実さを3段階に分けて設計する。

| 状態 | 鳴るか | 仕組み |
|---|---|---|
| ① アプリの画面を表示中(専用の「おやすみ画面」) | ◎ 確実 | ページ内タイマー+音声再生。Wake Lock APIで画面ロックによる停止を防ぐ |
| ② アプリを開いたまま画面OFF/他アプリ使用中 | ○ 概ね鳴る | **無音オーディオをループ再生して待機**し、時刻が来たら アラーム音に切替+通知を表示。音声セッションが生きている限りバックグラウンドでも動く |
| ③ アプリを完全に終了(タスクから削除) | ✕ 不可能 | Webの仕様上どうにもならない。**前夜に「アラームをセットしてね」と気付ける工夫**(後述)で補助 |

- ②が「閉じていても通知」の実現手段。Android Chrome では安定して動く見込み。
  iPhone(Safari/ホーム画面追加)は音声バックグラウンド再生の制約が強く、
  実機検証の結果次第で「iPhoneは①推奨」と案内する。
- ③の補助策: 就寝時間帯に開いたときの「セット確認」表示、
  ホーム画面のアイコンバッジ、READMEでの運用案内
  (寝る前にアプリを開いて充電置きする)。

## 機能仕様

### 1. アラーム(複数登録可)

- 時刻、ラベル(例: 出勤)、有効/無効スイッチ
- 曜日指定: 月〜金がデフォルト。個別にON/OFF可(土曜出勤の人にも対応)
- **祝日除外スイッチ**(アラームごと): ONなら祝日・カスタム休日はスキップ
- アラーム音の選択と音量、スヌーズ(間隔・回数)
- **次回鳴動の表示**が本アプリの肝:
  「次は 7/21(火) 7:00 — 7/20(月・海の日)はスキップします」のように
  スキップ理由まで見せて、ユーザーが安心して眠れるようにする

### 2. 祝日データ

- **内蔵データ**: 内閣府の祝日CSV由来のデータ(当年±2年分)をアプリに同梱。
  オフラインでも判定できる
- **自動更新**: 起動時に holidays-jp API
  (`https://holidays-jp.github.io/api/v1/date.json`)から最新を取得して
  LocalStorage にキャッシュ。取得失敗時は内蔵+前回キャッシュで動く
- 祝日は毎年2月に翌年分が官報で確定するため、自動更新は必須機能とする

### 3. カスタム休日

- カレンダー画面で日付をタップして「休み」を追加/解除
- 祝日は色付きで表示(タップで名称表示)。休みの日・祝日・アラームが鳴る日が
  ひと目でわかるカレンダーにする
- よく使う一括登録プリセット: 「12/29〜1/3(年末年始)」ボタンなど

### 4. 鳴動画面・おやすみ画面

- **おやすみ画面**: 寝る前に開いておく専用画面。現在時刻・次回アラーム・
  「祝日スキップ中」表示。画面を暗くしつつ Wake Lock で待機
- **鳴動中画面**: 大きな停止ボタン+スヌーズボタン。通知からも停止可能

### 5. 設定

- 通知の許可状態の表示とテスト鳴動ボタン(「音が鳴るか今すぐ確認」)
- 祝日データの最終更新日時と手動更新
- スヌーズ既定値、アラーム音の追加(端末の音声ファイル選択)

## データ設計(LocalStorage)

- `alarms`: [{id, time, label, days[0-6], skipHolidays, sound, volume, snooze, enabled}]
- `holidays`: {"2026-07-20": "海の日", ...}(キャッシュ+取得日時)
- `customHolidays`: ["2026-12-30", ...]
- `settings`: 既定スヌーズ、音量、通知許可の案内済みフラグ

## 作成する順番(おすすめ)

0. **技術検証(最初にやる・最重要)**: 実機の Android / iPhone で
   「無音再生で待機 → 画面OFF・他アプリ操作中にアラーム音+通知が出るか」を
   最小のテストページで確認する。ここの結果が②の設計を決める。
   ダメな環境では「①おやすみ画面推奨」に方針転換
1. **鳴動日計算エンジン**: 「今から見て次に鳴るのはいつか」を計算する純ロジック
   (曜日+祝日+カスタム休日の除外)。内蔵祝日データもここで用意。
   UIなしでテストできるので最初に固める
2. **骨組み**: アラーム一覧・追加/編集画面。次回鳴動とスキップ理由の表示
3. **鳴動(①)**: 画面表示中のアラーム音・スヌーズ・停止、Wake Lock、おやすみ画面
4. **バックグラウンド(②)**: 無音再生待機+通知。手順0の結果を反映
5. **カレンダー**: 祝日表示+カスタム休日の追加/解除+年末年始プリセット
6. **祝日自動更新**: holidays-jp からの取得とキャッシュ
7. **仕上げ**: PWA化(ホーム画面追加・オフライン)、README、公開設定

順番の理由: このアプリの価値は「正しくスキップする計算」と「ちゃんと鳴る」の
2点に集約されるので、リスクの高い「鳴る」(手順0)と、テストしやすい「計算」
(手順1)を最初に片付ける。カレンダーUIや自動更新は土台の上に後から載せられる。

## 注意点・アドバイス(設計メモ)

- **祝日判定は日付文字列(JST)で行う**。UTC変換を挟むと前日扱いになる
  バグが定番なので `YYYY-MM-DD` の文字列比較で統一する
- 「23:50に翌日の準備アラーム」のような**日付をまたぐ次回計算**に注意
- スヌーズ中に日付が変わっても祝日判定はアラーム本来の日付で行う
- 通知許可はいきなり求めず、最初のアラーム保存時に理由を添えて求める
- 端末の**マナーモード/サイレントスイッチでは Web の音声は消えない**
  (メディア音量扱い)のは目覚ましには好都合だが、メディア音量が0だと
  鳴らないので、おやすみ画面で音量チェックを出す
