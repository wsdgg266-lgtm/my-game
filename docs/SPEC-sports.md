# ⚾🏀⚽ スポーツ観戦アプリ 仕様案(検討ドラフト)

「今日どの試合があって、どこで見れて、結果はどうだったか」が1画面でわかる、
自分専用の観戦ハブアプリ。

既存の「かいわすれナシ!」と同じ構成(ビルド不要・単一HTML・PWA・LocalStorage)で作る。
公開方法(GitHub Pages のどのURLに置くか)は完成後に決める。

## 対象スポーツ(初期セット)

| スポーツ | リーグ | データ自動取得 |
|---|---|---|
| プロ野球 | NPB(セ・パ12球団) | TheSportsDB (league 4591) |
| サッカー | J1リーグ | TheSportsDB (league 4633) |
| バスケ | B.LEAGUE (B1) | TheSportsDB にあるか要検証。無ければ手動+リンク運用 |
| 海外 | MLB・NBA(仮。変更・追加可) | TheSportsDB(カバー良好) |

リーグはアプリ内の設定データ(リーグID表)で管理し、後から追加・削除しやすくする。

## データの取り方(方針: 自動取得+リンク補完)

- **日程・対戦カード・結果**: TheSportsDB 無料API(APIキー `123`)から
  ブラウザが直接取得。取得結果は LocalStorage にキャッシュし、
  オフライン時・API障害時は「最後に取得したデータ + 取得日時」を表示する。
- **リスクと保険**: TheSportsDB は有志更新のため、日本のリーグは
  結果反映が遅い・抜けがある可能性がある。全試合カードに
  公式サイト・スポーツナビ等へのワンタップリンクを常設して補完する。
- **放送・配信チャンネル(要望②)**: 自動取得できるデータソースが存在しないため
  三段構えにする:
  1. **リーグごとの視聴先プリセット**(例: J1→DAZN、B1→バスケットLIVE、
     NPB→DAZN/スカパー/球団別 など)を試合カードに自動表示。プリセットは編集可能
     (放映権は毎年変わるため)
  2. **試合ごとの手動メモ**でプリセットを上書きできる(「今日は地上波○○」など)
  3. 番組表検索へのワンタップリンク

## 画面構成

1. **ホーム**: 今日〜今後の試合タイムライン。フォロー中のチーム・選手の試合を上部に強調
2. **スポーツタブ(要望⑤)**: 野球/サッカー/バスケ/海外 で全画面をフィルタ
3. **日程(①③)**: 対戦カード・日時・球場/会場・視聴先を試合カードで一覧
4. **結果(④)**: 終了した試合のスコア一覧
5. **フォロー(⑤⑥)**: チームのフォローと、選手の登録(名前+所属チーム)。
   選手を選ぶと所属チームの試合に絞って①〜④を表示(方針: 個人成績は扱わない)
6. **設定**: 視聴先プリセット編集、データ再取得、キャッシュクリア

## データ設計(LocalStorage)

- `follows`: フォロー中スポーツ / チーム / 選手(選手 = 名前 + 所属チームID)
- `cache`: リーグIDごとの試合データと取得日時
- `broadcastPresets`: リーグ → 視聴先(編集可の初期値入り)
- `broadcastOverrides`: 試合ID → 手動メモ

## 作成する順番(おすすめ)

0. **技術検証(最初にやる・最重要)**: TheSportsDB から NPB / J1 / B1 / MLB / NBA の
   直近の日程と結果が実際にブラウザから取れるか確認する。
   取れないリーグはこの時点で「手動+リンク運用」に方針転換する
1. **骨組み**: 画面レイアウト+スポーツ選択タブ(⑤)。データは仮でよい
2. **日程・対戦カード(①③)**: API取得 → 試合カード表示 → キャッシュ
3. **結果(④)**: 過去試合のスコア表示
4. **視聴媒体(②)**: プリセット+手動メモ+リンク
5. **フォロー(⑤⑥の完成)**: チーム・選手の登録と絞り込み、ホームの「今日の注目」
6. **仕上げ**: PWA化(オフライン対応・ホーム画面追加)、公開方法の決定

順番の理由: ①③④はAPI頼みなので実現性を最初に検証。②はデータが無く設計の自由度が
高いので後回しでも安全。⑤⑥は①〜④のフィルタなので土台の上に最後に載せる。
