# 🎆 花火写真アプリ 仕様書

> **実装状況**: `fireworks/` に実装済み(アプリ名: **ハナビカメラ**)。

スマホのカメラで「花火がきれいに写った1枚」を撮るためのアプリ。

普通のカメラアプリで花火を撮ると、花火は一瞬で消えるので**点みたいにしか写らない**か、
逆に明るすぎて**白く飛ぶ**。きれいな花火写真は本来、一眼レフを三脚に固定して
数秒間シャッターを開けっぱなしにする「長時間露光」で撮るもので、スマホの標準カメラでは難しい。

このアプリは、その長時間露光を**連写＋比較明合成**で再現する。
シャッターを押している間カメラの映像を高速に取り込み続け、
各フレームの**明るい部分だけを重ねる**(比較明合成)ことで、
暗い夜空はそのまま暗く保ちつつ、花火の光跡だけが伸びていく1枚ができあがる。

既存アプリ(かいわすれナシ!・スポカレ!・ふくらぶ!・ピコラン!)と同じ構成で作る:

- ビルド不要・単一HTML(`fireworks/index.html`)・依存ライブラリなし
- PWA対応(ホーム画面に追加してフルスクリーンで起動)
- 写真は端末の外に一切送信しない(処理はすべてブラウザ内で完結)

## 決定事項(ヒアリング結果)

| 項目 | 決定 |
|---|---|
| 中核機能 | **アプリ内カメラで撮影＋自動合成** と **撮影済み写真の加工・合成** の2本立て |
| 対応デバイス | **iPhone / Android 両方**(共通で動く連写＋合成をベースにし、使える端末でだけ露出・ピント制御を追加で有効化) |
| 保存 | **端末に保存(ダウンロード)**のみ。アプリ内ギャラリーやSNS共有ボタンは作らない |
| UI | **かんたんモード＋詳細モード**の2段構え。通常はかんたん、必要な人だけ詳細を開く |

## 画面構成

単一画面のモード切替で構成する。

```
┌─────────────────────────┐
│ 🎆 ハナビカメラ    [📷ライブ|🖼写真から] ⚙ │  ← ヘッダー
├─────────────────────────┤
│                                         │
│        カメラプレビュー                  │  ← 撮影中は合成中の絵に切り替わる
│      (撮影中は光跡が伸びていく)          │
│                                         │
├─────────────────────────┤
│  [打ち上げ] [スターマイン] [仕掛け花火]  │  ← プリセット(かんたんモード)
│              (  ●  )                    │  ← シャッター(押しっぱなしで合成)
└─────────────────────────┘
```

撮影を止めると**仕上げ画面**にかぶさる。ここで自動補正済みの絵を見ながら
スライダーで微調整し、「保存」で端末に書き出す。

## 1. ライブ撮影モード

### 撮影の流れ

1. シャッターボタンを**押している間**、カメラ映像を毎フレーム取り込む
2. 取り込んだフレームを、それまでの合成結果に**比較明合成**(canvas の `lighten`)で重ねる
3. 画面には合成中の絵をそのまま出すので、**光跡が伸びていく様子がリアルタイムで見える**
4. 指を離す or 上限秒数に達すると停止し、仕上げ画面へ

シャッターは**押しっぱなし**が基本だが、短く1回タップした場合は
「上限秒数まで撮りっぱなし」に切り替わる(もう一度タップで停止)。
三脚やフェンスに固定しているとき、指を触れ続けなくて済むようにするため。

### カメラの制御

`getUserMedia` で背面カメラ(`facingMode: environment`)を最大 1920×1080 で開き、
`MediaStreamTrack.getCapabilities()` で使える制御を調べて、使えるものだけ適用する。
端末差が大きいので**すべて任意扱い**で、失敗しても撮影自体は成立させる。

| 制御 | ねらい | 使えないとき |
|---|---|---|
| ピント固定(`focusMode: manual` + `focusDistance` 最遠) | 暗い夜空でピントが迷って光跡がボケるのを防ぐ | 自動のまま(`continuous`) |
| ホワイトバランス固定(`whiteBalanceMode: manual`) | フレームごとに色が変わって合成結果がにごるのを防ぐ | 自動のまま |
| 露出固定(`exposureMode: manual` + `exposureTime` / `iso`) | 花火が白飛びしないよう、やや暗めで固定する | `exposureCompensation` で代替、それも無ければ取り込み時にデジタルで暗くする |

適用できた制御は詳細モードに「カメラ制御: 露出◯ ピント◯ WB×」の形で表示し、
うまく撮れないときの切り分けができるようにする。

### プリセット(かんたんモード)

花火の種類で最適な合成時間と光跡の残し方が違うので、3つのプリセットで選ばせる。

| プリセット | 上限秒数 | 光跡の残り | ねらい |
|---|---|---|---|
| 打ち上げ(単発) | 4秒 | 100%(消さない) | 1発が開いて散るまでをまるごと1枚に |
| スターマイン(連発) | 8秒 | 98.5%/フレーム | 重ねすぎて真っ白になるのを防ぎつつ連発の迫力を出す |
| 仕掛け花火・ナイヤガラ | 6秒 | 97%/フレーム | 光の量が多い被写体なので早めに減衰させる |

「光跡の残り」は、新しいフレームを重ねる前に合成結果をわずかに暗くする割合。
100%なら消えないので光跡が全部残り、値を下げるほど古い光跡から順に消えていく。

### 詳細モード

かんたんモードでは隠す。開くと以下を直接いじれる。

- **合成する秒数の上限**(1〜15秒)
- **明るさ**(露出補正 / デジタルゲイン、-2〜+1段)
- **光跡の残り**(90〜100%)
- **ピント固定・WB固定**の ON/OFF
- **三分割グリッド**の表示(構図合わせ用)
- **手ブレ警告**: 加速度センサーで端末の揺れを検知し、撮影中に揺れたら警告を出す
  (iOS はセンサー利用に許可が必要なので、ONにしたときに許可ダイアログを出す)

## 2. 写真から合成モード

すでにカメラロールにある花火写真を読み込んで、同じ処理をかける。

- **複数枚を選ぶ** → 比較明合成で1枚にまとめる(連写した花火写真を1枚に合成できる)
- **1枚だけ選ぶ** → 合成なしで仕上げ調整だけかける

1枚目の写真の縦横サイズを基準にし、2枚目以降はそこに収まるよう拡大縮小して重ねる。
EXIF の回転情報は `createImageBitmap` の `imageOrientation: 'from-image'` で反映する。
メモリ対策として長辺 3000px を上限に縮小する。

## 3. 仕上げ(現像)

撮影・合成の直後に**自動補正**をかけた状態で表示する。

### 自動補正の中身

夜空を撮ると、街明かりの照り返し(光害)で夜空が黒ではなく**茶色っぽく浮く**。
これを取り除くのが花火写真では一番効く。

1. 合成結果を縮小してRGB各チャンネルのヒストグラムを作る
2. 画面の大半は夜空なので、**下から25%の明るさ**をそのチャンネルの「かぶり」とみなす
3. かぶりを**チャンネルごとに**引く(オレンジっぽいかぶりが色ごと消える)
4. 上位0.5%の明るさが白飛びしない範囲でコントラストを伸ばす(伸ばしすぎ防止に上限1.6倍)

### 煙を消す

比較明合成の最大の弱点が**煙**。花火に照らされた煙は夜空より明るいので、
「明るいほうを残す」合成では一度写り込むと最後まで消えない。連発のあとや
風のない日は、後半の花火が白い煙にかすんでしまう。

かぶり除去が画面全体で一律に引くのに対して、こちらは**場所ごとに**引く。

1. 画面をマス目(縮小画像上で8px角、およそ32×18)に区切る
2. マスごとに**下位10%の明るさ**を求める。煙は一様に明るいのでこの値が持ち上がり、
   花火は光と闇が同居するのでこの値は夜空のままになる
3. マス内の明暗差が大きい(上位75%と下位10%の差が30超)マスは**花火が写っている**と
   判断して煙の判定から外し、周囲の値で埋める。花火自体を消してしまわないため
4. 3×3で3回ならして、花火のかたちに引きずられない滑らかな「煙の地図」にする
5. 全体のかぶり(前項の黒レベル)を超えたぶんが、その場所の煙の量。
   建物や観客席の明かりまで削らないよう、引く量には上限(画面の明暗差の35%)をかける
6. 地図を2段階で表示サイズまで引き伸ばし、画素ごとに引いてからトーンカーブに通す

薄いムラしか見つからない(最大でも8/255未満)写真では、引いても見た目が変わらないので
スライダー自体を無効にして「煙なし」と表示する。

撮影時に**光跡の残り**を下げておくと、古い煙から順に消えていくので併用が効く。

### 手動スライダー

| 項目 | 効果 |
|---|---|
| かぶり除去 | 自動で求めた夜空の明るさを、どれだけ引くか(0〜100%) |
| 煙を消す | 場所ごとに求めた煙の濃さを、どれだけ引くか(0〜100%、既定50%) |
| 明るさ | ガンマ補正。花火の淡い部分を持ち上げる |
| コントラスト | 夜空と花火のメリハリ |
| 鮮やかさ | 花火の色を出す。上げすぎると不自然になる |

処理は**LUT(256段の変換表)＋彩度合成**の1パスで行い、
画面表示は縮小画像に、保存時だけ元の解像度にかける。
スライダーを動かしたときの反応を軽くするための構成。

## 4. 保存

`canvas.toBlob()` で JPEG(品質92%)にして、`<a download>` で端末に保存する。
ファイル名は `hanabi-YYYYMMDD-HHMMSS.jpg`。

iPhone では保存後に「写真」アプリへ入れる操作が必要な場合があるので、
「画像を長押し→"写真"に追加でも保存できます」というヒントを添える。

## 5. 撮り方のコツ(アプリ内ヘルプ)

長文の撮影ガイドは作らないが、初回起動時と ? ボタンから短いヒントを出す。

- **端末を固定する**(手すり・三脚・カバンの上)。合成中に動くと光跡が二重になる
- **打ち上がる音が聞こえたらシャッターを押す**。開いてからでは遅い
- **横位置で、空を広めに**。花火は思ったより大きく開く
- 白飛びするときは詳細モードの**明るさをマイナス**に

## 技術構成

- HTML / CSS / JavaScript のみの単一ファイル、依存ライブラリなし
- カメラ: `getUserMedia` + `MediaStreamTrack.applyConstraints`
- 合成: Canvas 2D の `globalCompositeOperation = 'lighten'`(比較明合成)
- 減衰: `globalCompositeOperation = 'multiply'` でグレーを塗る
- 現像: `getImageData` + チャンネル別LUT
- 設定は LocalStorage に保存(写真は保存しない)
- PWA(`manifest.webmanifest` + `sw.js`)。カメラは HTTPS 必須なので
  公開URL(GitHub Pages / Vercel)経由で使う

## 対応環境と制約

- **HTTPS 必須**。`file://` で開くとカメラが使えない(写真から合成モードは使える)
- iOS Safari はブラウザからシャッター速度・ISO を直接指定できないため、
  長時間露光は連写＋合成でのみ再現される(本仕様はこれを前提にしている)
- 合成中は端末が発熱しやすいので、上限秒数を設けて自動停止する
